# Circuits.com Schema Report, 10 November 2026

**Scope:** live https://circuits.com plus the repo source. I fetched nine live pages with curl, and each one is byte-identical to the file on `main`. Markup that JavaScript adds (`jobs.html`, `profile.js`) was read from the source, because Supabase is not reachable from this sandbox. The bundled `parse_html.py` refused the sandbox proxy, so I extracted the JSON-LD with a short script instead.

**Schema score: 45 / 100.** The homepage block is clean. The only markup that could win a rich result, JobPosting, is placed in a way Google's guidelines forbid. The profile pages, where most of the value is, emit their schema only from JavaScript, and today no profile page has been generated.

## What's there

| Where | Type | How delivered | Status | Issues |
|---|---|---|---|---|
| `/` (index.html) | Organization + WebSite with SearchAction, in one `@graph` | Static HTML | ✅ Valid | No `sameAs`, contact point or founders. SearchAction gets no SERP feature (sitelinks search box retired Nov 2024). Harmless. |
| `/jobs` (jobs.html:141-152) | Array of up to 50 `JobPosting` | JS, after the Supabase fetch | ❌ Violates guidelines | See S1 |
| `/<handle>` profiles (profile.js:706-723) | Organization (+ AggregateRating when reviews exist) | JS only | ⚠️ Valid but weak | See S2 |
| `/about`, `/contact`, `/browse`, `/clubs`, `/results`, samples | none | | ⚠️ | No BreadcrumbList anywhere on the site |

No Microdata or RDFa was found. No deprecated types are used (no HowTo, FAQPage, SpecialAnnouncement and so on).

## Findings

### S1. Critical: JobPosting on the list page
`/jobs` adds one JobPosting for every open role to a single listing page. Google requires JobPosting to sit on the page for **one** job, and markup on list pages can bring a structured-data manual action. Beyond where it sits:
- `url` is `/jobs?q=<first keyword>`, so several jobs share a URL and none of those URLs shows that particular job.
- `employmentType` is hard-coded to `FULL_TIME` whatever the job is.
- `jobLocation.address` is free text. Google wants a `PostalAddress` with `addressCountry`, or `jobLocationType: TELECOMMUTE` for remote roles.
- `description` falls back to the title, which makes thin descriptions.
- `hiringOrganization.sameAs` points to the circuits.com profile, which currently returns 404 because no profiles are generated. It should be the company's own website.
- `directApply: true` is arguable, because applying needs a circuits.com sign-in first.

**Fix:** delete the injection at `jobs.html:141-152` now (this matches H2 in today's full audit). Bring JobPosting back only with `/jobs/<id>` pages, using the `job_detail_page_template` in the generated file.
**How we'd know it failed:** Search Console > Enhancements > Job postings still shows `/jobs` items 2 weeks after deploy, or a manual action shows up.
**Leading indicator:** the Job postings enhancement report drops to 0 items, and later counts only `/jobs/<id>` URLs.

### S2. High: profile schema is JS-only and isn't a ProfilePage
`profile.js` injects a bare Organization after the data loads. Google does render JS, but the raw HTML of a profile says "Loading...". If the fetch fails or is slow, there's no entity at all. The page is also a profile hosted on a directory, which is what `ProfilePage` with `mainEntity` is for, and nothing ties it to the site's WebSite or to a breadcrumb trail.

**Fix:** have `tools/build-profiles.js` write the `company_profile_template` (ProfilePage + Organization + BreadcrumbList) into each generated page as static HTML, then remove `jsonLd()` from `profile.js`. JSON-escape the values, and escape `<` as `<`. **Depends on** C1/C2 in the full audit (the generator has to run first).
**How we'd know it failed:** `curl -s https://circuits.com/<handle> | grep -c ld+json` returns 0, or the Rich Results Test shows no ProfilePage.
**Leading indicator:** Search Console > Enhancements > Profile page item count.

### S3. Medium: dormant AggregateRating
Buyer reviews are switched off (`profile.js:451-453` sets `reviews = []`), so no rating is emitted today. If reviews come back, the code will add an AggregateRating with no individual `Review` items behind it. That's acceptable only if the reviews are visible on the page and come from real, independent buyers. Keep the moderation, and add `review` items when you switch it back on.

### S4. Low: homepage Organization is thin
Add `email` and `contactPoint`, plus founders if the owners want them named. `contact.html` can hide Mike's card, so ask before naming him in schema. Add `sameAs` only once official profiles (LinkedIn, a company registry) exist. This ties into the full audit's E-E-A-T finding that nobody is named on About or in the schema. See `homepage_index_html` in the generated file.

### Info
- `/company.html` serves the raw template with `{{TITLE}}` placeholders. It's blocked in robots.txt, so it isn't indexed, but don't add schema to it with literal placeholders.
- Sample pages are `noindex,nofollow`. Keep any schema off them.

## Not recommended
- **FAQPage** on About or How It Works: Google retired FAQ rich results on 7 May 2026.
- **HowTo** on How It Works: deprecated in 2023.
- **ItemList on `/results` or `/browse`**: it does nothing while the list is built by JS and the pages are thin (see H1 in the full audit). Revisit once static keyword pages exist.
